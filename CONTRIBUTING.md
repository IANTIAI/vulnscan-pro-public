# Contributing

1. Open an issue describing the change or bug. Do not attach real scan databases or reports.
2. Keep changes scoped and document new configuration, data sources, and network traffic.
3. Provide synthetic examples only. Never commit `*.db`, scan output, PDF reports, secrets, or customer IPs.
4. Before proposing a change, check Python syntax and manually verify affected UI/report paths in an authorized test environment.
5. Explain any security, privacy, or BSI mapping impact in the pull request.
